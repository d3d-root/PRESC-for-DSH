# PRESC memory — editable bundle

This folder is an exact copy of a PRESC memory bundle used by DeepSeek
Harness. You may edit the Markdown files here. When you are done, the owner
sends the folder back and it is copied over the installed memory.

**Read the validation rules before editing.** The bundle is machine-validated:
a file that breaks a rule is rejected and the whole bundle falls back to
"pending", so the owner loses the delivered project dossiers until it is fixed.

---

## 1. What this bundle is

A PRESC memory bundle has three parts:

| Part | Path | Role |
|---|---|---|
| Canonical sources | `prompt.md`, `security-posture.md`, `lore.md`, `user.md`, `context/research-index.md` | The fixed lore, delivered into every session |
| Research | `research/NN-topic.md` | The rationale behind settled decisions |
| Project dossiers | `artifacts/INDEX.md`, `artifacts/projects/*.md` | One summary per project, validated and delivered in full |

The canonical sources are the input. The dossiers are a derived summary: each
dossier must correspond to one `###` heading in `lore.md`.

---

## 2. What you may edit

### Safe to edit freely

- **`prompt.md`** — working rules: priorities, style, boundaries.
- **`security-posture.md`** — security frame and disclosure rules.
- **`user.md`** — durable collaboration preferences only.
- **`research/NN-topic.md`** — one decision per file. Add files, edit text.
- **`context/research-index.md`** — one line per research document.

### Editable, but the bundle must stay consistent

- **`lore.md`** — project history. Every `###` heading is a project. Renaming,
  adding, or removing a heading changes the expected dossier set.
- **`artifacts/projects/*.md`** — one dossier per project.
- **`artifacts/INDEX.md`** — must link every dossier with an exact link.

### Do not edit

- `artifacts/.artifact-manifest.json` — generated by the validator; not present
  in this bundle on purpose. It is rebuilt when the bundle is finalized.
- Any file outside this folder.

## 3. Validation rules (mandatory)

The validator is `vendor/artifact-generator.py` in the installed plugin. These
are the exact rules it enforces. Breaking any of them fails validation.

### 3.1 Language

Every dossier and `artifacts/INDEX.md` **must be written in English prose**.

The check is literal, not a translation heuristic:

- No non-Latin alphabetic characters at all (no Cyrillic, Greek, CJK).
  Latin letters with diacritics are fine.
- At least 40 words of prose outside code blocks and outside `#` heading lines.
- At least 6 distinct words from this list, at least 6 occurrences total, and at
  least 8% of all prose words must be from this list:

  ```
  and are by each for from is it its must of only our should that the their
  they this through to under use used uses using was we when where which while
  will with without your
  ```

Write normal English sentences. Do not write telegraphic fragments — a file
made of short bullet fragments with no function words will fail the ratio test.

### 3.2 Dossier structure

Each `artifacts/projects/<slug>.md` must satisfy all of these:

1. The first non-empty line is exactly `# <project title>`, where the title is
   character-for-character the `###` heading text from `lore.md`.
2. It contains all nine level-two sections, spelled exactly:

   ```
   ## Canon
   ## Goal and Outcome
   ## Architecture and Components
   ## Decisions and Constraints
   ## Operating Workflow
   ## Lessons and Rules
   ## Sources
   ## Unknowns
   ## When to Revisit
   ```

3. Each section body has at least 12 characters of non-whitespace text. An empty
   section fails.
4. The `## Sources` section cites `lore.md` and every research document the
   project references in `lore.md`, using the exact relative path, for example
   `research/07-x-reply-farm.md`.

### 3.3 Index structure

`artifacts/INDEX.md` must satisfy all of these:

1. The first non-empty line starts with `# `.
2. It contains, for every project, an exact link of the form
   `[<project title>](projects/<slug>.md)` — the title and the slug must match
   exactly.
3. It contains no `projects/...md` link for a project that does not exist.

### 3.4 Project set

- The set of files in `artifacts/projects/` must equal the set of `###`
  headings in `lore.md`, one file per heading, no extras, no orphans.
- The file name is derived from the heading: a two-digit ordinal, then a
  lowercased ASCII slug of the title. Example: the third `###` heading
  "Payment Rails" becomes `03-payment-rails.md`.

**If you rename a heading in `lore.md`, you must rename the corresponding
dossier file to the new slug and update its link in `INDEX.md`.**
The ordinal follows the heading order in `lore.md`; reordering headings
renumbers the files.

## 4. What a dossier should contain

The nine sections are not decoration. Fill them like this:

| Section | What belongs there |
|---|---|
| Canon | The settled statement of what this project is. Present tense, no hedging. |
| Goal and Outcome | Why it exists and what actually came of it. |
| Architecture and Components | Concrete parts: services, files, data model, tooling. |
| Decisions and Constraints | Decisions with the constraint that forced them, and what each rules out. |
| Operating Workflow | The repeatable procedure, in order. |
| Lessons and Rules | Failures and the rule each produced. State the failure, not only the conclusion. |
| Sources | `lore.md` plus the `research/` documents that support it. |
| Unknowns | What is genuinely not established. Do not invent numbers. |
| When to Revisit | The concrete trigger that reopens the decision. |

Two habits matter more than length:

- **Separate observation from interpretation.** "The webhook retried and the
  balance changed twice" is an observation; "idempotency was missing" is the
  finding.
- **Never invent facts.** If a number, a name, or an outcome is not in the
  source material, put it under `Unknowns` instead of guessing.

---

## 5. How the result is applied

The owner sends this folder back. Applying it:

1. Files are copied over the installed memory, preserving this exact layout.
2. The validator runs. If every rule above holds, the bundle becomes `ready`
   and the dossiers are delivered in full into every session.
3. If a rule fails, the validator reports the exact file and reason, and the
   bundle stays `pending` until it is corrected.

So: **do not hand back a partially edited bundle.** If you change `lore.md`,
finish the matching dossiers and `INDEX.md` in the same pass.

---

## 6. Checklist before handing back

- [ ] Every `###` heading in `lore.md` has exactly one file in
      `artifacts/projects/`, named `<ordinal>-<slug>.md`.
- [ ] Each dossier's first line is `# ` plus the exact heading text.
- [ ] All nine `##` sections present in every dossier, none empty.
- [ ] `## Sources` in every dossier cites `lore.md` and its research files.
- [ ] `INDEX.md` has one exact `[Title](projects/slug.md)` link per project,
      and no other project links.
- [ ] Every edited dossier and `INDEX.md` is English prose, no Cyrillic.
- [ ] Every research document referenced from `lore.md` exists in `research/`.
- [ ] `context/research-index.md` lists every file in `research/`.
