# Память PRESC — редактируемый бандл

Эта папка — точная копия бандла памяти PRESC, который использует DeepSeek
Harness. Здесь можно править Markdown-файлы. Когда закончишь, владелец забирает
папку и копирует её поверх установленной памяти.

**Прочитай правила валидации до того, как начнёшь править.** Бандл проверяется
машиной: файл, нарушивший правило, отвергается, и весь бандл падает в статус
`pending` — то есть владелец перестаёт получать досье проектов, пока ошибка не
исправлена.

---

## 1. Что это за бандл

У бандла памяти PRESC три части:

| Часть | Путь | Роль |
|---|---|---|
| Канонические источники | `prompt.md`, `security-posture.md`, `lore.md`, `user.md`, `context/research-index.md` | Фиксированный лор, доставляется в каждую сессию |
| Исследования | `research/NN-topic.md` | Обоснование принятых решений |
| Досье проектов | `artifacts/INDEX.md`, `artifacts/projects/*.md` | По одной сводке на проект, валидируется и доставляется целиком |

Канонические источники — это вход. Досье — производная сводка: каждое досье
должно соответствовать одному заголовку `###` в `lore.md`.

---

## 2. Что можно править

### Можно править свободно

- **`prompt.md`** — правила работы: приоритеты, стиль, границы.
- **`security-posture.md`** — рамки безопасности и правила раскрытия.
- **`user.md`** — только устойчивые предпочтения в совместной работе.
- **`research/NN-topic.md`** — одно решение на файл. Добавляй файлы, правь текст.
- **`context/research-index.md`** — по строке на каждый документ исследования.

### Править можно, но бандл должен остаться согласованным

- **`lore.md`** — история проектов. Каждый заголовок `###` — это проект.
  Переименование, добавление или удаление заголовка меняет ожидаемый набор
  досье.
- **`artifacts/projects/*.md`** — по одному досье на проект.
- **`artifacts/INDEX.md`** — должен ссылаться на каждое досье точной ссылкой.

### Править нельзя

- `artifacts/.artifact-manifest.json` — генерируется валидатором. В этом бандле
  его нет намеренно: он пересоздаётся при финализации.
- Любые файлы за пределами этой папки.

---

## 3. Правила валидации (обязательные)

Валидатор — `vendor/artifact-generator.py` в установленном плагине. Ниже точные
правила, которые он проверяет. Нарушение любого из них — провал валидации.

### 3.1 Язык

Каждое досье и `artifacts/INDEX.md` **должны быть написаны английской прозой**.

Проверка буквальная, это не эвристика перевода:

- Ни одного нелатинского алфавитного символа (никакой кириллицы, греческого,
  CJK). Латинские буквы с диакритикой допустимы.
- Не менее 40 слов прозы вне блоков кода и вне строк-заголовков `#`.
- Не менее 6 различных слов из списка ниже, не менее 6 вхождений всего, и не
  менее 8% всех слов прозы должны быть из этого списка:

  ```
  and are by each for from is it its must of only our should that the their
  they this through to under use used uses using was we when where which while
  will with without your
  ```

Пиши нормальные английские предложения. Не пиши телеграфным стилем: файл из
коротких обрывочных пунктов без служебных слов не пройдёт проверку доли.

### 3.2 Структура досье

Каждый файл `artifacts/projects/<slug>.md` должен удовлетворять всему этому:

1. Первая непустая строка — ровно `# <название проекта>`, где название
   посимвольно совпадает с текстом заголовка `###` из `lore.md`.
2. В нём есть все девять разделов второго уровня, написанные точно так:

   ```
   ## Canon
   ## Goal and Outcome
   ## Architecture and Components
   ## Decisions and Constraints
   ## Operating Workflow
   ## Lessons and Rules
   ## Sources
   ## Unknowns
   ## When to Revisit
   ```

3. Тело каждого раздела содержит минимум 12 символов непробельного текста.
   Пустой раздел — провал.
4. Раздел `## Sources` ссылается на `lore.md` и на каждый документ исследований,
   который проект упоминает в `lore.md`, — точным относительным путём, например
   `research/07-x-reply-farm.md`.

### 3.3 Структура индекса

`artifacts/INDEX.md` должен удовлетворять всему этому:

1. Первая непустая строка начинается с `# `.
2. Для каждого проекта есть точная ссылка вида
   `[<название проекта>](projects/<slug>.md)` — название и slug должны совпадать
   точно.
3. В нём нет ссылок `projects/...md` на проекты, которых не существует.

### 3.4 Набор проектов

- Набор файлов в `artifacts/projects/` должен совпадать с набором заголовков
  `###` в `lore.md`: один файл на заголовок, без лишних, без осиротевших.
- Имя файла выводится из заголовка: двузначный порядковый номер, затем
  приведённый к нижнему регистру ASCII-slug названия. Пример: третий заголовок
  `### Payment Rails` превращается в `03-payment-rails.md`.

**Если переименовал заголовок в `lore.md`, нужно переименовать
соответствующий файл досье под новый slug и обновить его ссылку в `INDEX.md`.**
Порядковый номер следует за порядком заголовков в `lore.md`; перестановка
заголовков перенумеровывает файлы.

## 4. Что должно быть в досье

Девять разделов — это не украшение. Заполняй их так:

| Раздел | Что туда писать |
|---|---|
| Canon | Устоявшееся утверждение, что это за проект. Настоящее время, без оговорок. |
| Goal and Outcome | Зачем он существует и что из этого реально вышло. |
| Architecture and Components | Конкретные части: сервисы, файлы, модель данных, инструменты. |
| Decisions and Constraints | Решения вместе с ограничением, которое их вызвало, и что каждое из них исключает. |
| Operating Workflow | Повторяемая процедура, по порядку. |
| Lessons and Rules | Ошибки и правило, которое каждая породила. Указывай саму ошибку, а не только вывод. |
| Sources | `lore.md` плюс документы `research/`, которые это подтверждают. |
| Unknowns | Что действительно не установлено. Не выдумывай числа. |
| When to Revisit | Конкретный триггер, который открывает решение заново. |

Две привычки важнее объёма:

- **Отделяй наблюдение от интерпретации.** «Вебхук повторился и баланс изменился
  дважды» — это наблюдение; «идемпотентности не хватало» — это вывод.
- **Никогда не выдумывай факты.** Если числа, названия или исхода нет в исходных
  материалах — пиши это в `Unknowns`, а не угадывай.

---

## 5. Как применяется результат

Владелец забирает эту папку обратно. Применение:

1. Файлы копируются поверх установленной памяти с сохранением этой структуры.
2. Запускается валидатор. Если все правила выше соблюдены, бандл становится
   `ready` и досье доставляются целиком в каждую сессию.
3. Если правило нарушено, валидатор сообщает точный файл и причину, и бандл
   остаётся в `pending`, пока ошибка не исправлена.

Отсюда: **не отдавай наполовину отредактированный бандл.** Если меняешь
`lore.md`, доделай соответствующие досье и `INDEX.md` в том же проходе.

---

## 6. Чек-лист перед тем, как отдать папку

- [ ] На каждый заголовок `###` в `lore.md` есть ровно один файл в
      `artifacts/projects/` с именем `<номер>-<slug>.md`.
- [ ] Первая строка каждого досье — `# ` плюс точный текст заголовка.
- [ ] Все девять разделов `##` присутствуют в каждом досье, ни один не пуст.
- [ ] `## Sources` в каждом досье ссылается на `lore.md` и свои файлы
      исследований.
- [ ] В `INDEX.md` по одной точной ссылке `[Название](projects/slug.md)` на
      проект и никаких других ссылок на проекты.
- [ ] Каждое изменённое досье и `INDEX.md` — английская проза, без кириллицы.
- [ ] Каждый документ исследований, упомянутый в `lore.md`, существует в
      `research/`.
- [ ] `context/research-index.md` перечисляет все файлы из `research/`.
